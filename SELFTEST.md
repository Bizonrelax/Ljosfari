# SELFTEST QWR v1.0 — золотой случай и проверки поставки

Запуск: `python3 qwr/bot/bin/qwr.py doctor` и `python3 qwr/bot/bin/qwr.py selftest`. Оценка токенов — модель qwr-bytes/1 (кириллица 4.4 байта на токен, прочее 3.6), это оценка, не точный счётчик.

## Золотой случай

Золотой случай прогоняет механику протокола на мета-утверждениях о самом протоколе (предметно-нейтрально, без предметной математики). Используется зарезервированный блок A9001–A9099 и задачи T9001+. В поставке артефакты сухой прогонки лежат в `fixrealm/` как примеры оформления.

Шаги и ожидаемое:

1. PLN захватывает роль: первый агент 201, второй на ту же роль 422 и берёт другого кандидата.
2. PLN создаёт задачу с оценкой 10^40 операций — отклонена с требованием декомпозиции; задача под потолком 10^6 создана с блоком номеров, артефактом и критерием приёмки.
3. WRK берёт задачу, guard проверяет номер из блока, пишет карточку A9001 со статусом emp и таблицу в data, строку INDEX и JOURNAL. Сдвиг: расширенный проверенный диапазон.
4. EUR по оператору «инверсия условия» создаёт гипотезу A9006 со статусом hyp и дешёвым тестом ≤10^5 операций; маркер «эврика» уходит в inbox и не повышает статус.
5. CHK другим агентом проверяет A9001: письменное доказательство плюс закрытая задача — переход emp→prf, заключение data/V9001.md. CHK проверяет A9006: явный контрпример — переход hyp→ref, заключение data/V9006.md. Чужие карточки CHK не правит.
6. WRK ревизией синхронизирует оси карточек с INDEX.
7. LIT ставит A9001 новизну knw с двумя названными источниками и датой проверки, заключение data/L9001.md.
8. Три этапа подряд без сдвига по ветке B901 — ветка получает park и записку с причиной.
9. INDEX.md генерируется из INDEX.tsv; index check не показывает дрейфа осей.

Артефакты поставки: `fixrealm/cards/A9001.md`, `A9006.md`; `fixrealm/data/A9001-race.tsv`, `A9006-counter.tsv`, `V9001.md`, `V9006.md`, `L9001.md`, `A9020-attempt.tsv`…`A9022-attempt.tsv`; строки `INDEX.tsv`, `JOURNAL.md`; парк `qwr/bot/a2a/park.tsv`.

## Проверки поставки (doctor)

- структура: GATE.txt, MANIFEST.json, словари, роли, модули, INDEX.tsv на месте;
- шлюз ≤3000 токенов;
- сумма модулей ≤6000 токенов;
- каждая карточка роли ≤800, каждый ролевой файл ≤2500;
- изоляция ролей: ни один ролевой файл не требует чтения другого;
- вход сессии каждой роли ≤18000;
- неизвестных словарных кодов нет; словарь целиком не грузится;
- манифест OK (хэши сходятся).

## Измеренная приёмка (оценка qwr-bytes/1)

Шлюз: 2548 токенов (лимит 3000). Сумма модулей: 4729 (лимит 6000).

Вход сессии по ролям = шлюз + карточка + ролевой файл + needs + срез 1500 + расшифровка 500:

## Соответствие приёмке ТЗ

- вход сессии не выше 18000, измерено и приложено — таблица выше, doctor PASS;
- ни один ролевой файл не требует чтения другого — doctor «изоляция» PASS;
- неизвестных кодов нет, словарь целиком не грузится — doctor PASS, dict load только встреченные коды;
- два агента на одну роль: один 201, второй 422 и берёт другую — selftest PASS;
- задача с оценкой 10^40 отклонена и декомпозирована — selftest PASS, сухая прогонка P0;
- EUR даёт гипотезу с дешёвым тестом, CHK проверяет, статус не завышен — сухая прогонка A9006 hyp→ref, A9001 emp→prf только с CHK;
- каждый этап сухой прогонки оставил артефакт в fixrealm — cards и data выше;
- три этапа без сдвига приводят к park — сухая прогонка B901, park check PASS;
- GUIDE позволяет вернуться после недели паузы без чтения чата — ритуал возврата в qwr/GUIDE.md.

## Повторный запуск

selftest работает в чистой временной песочнице и не трогает боевые результаты. Сухая прогонка против боевого репозитория идемпотентна по задачам (повторное создание существующей задачи отклоняется) и дозаписывает журнал; для чистой повторной прогонки сбросьте тестовые файлы блока A9001–A9099 и задачи T9001+.
